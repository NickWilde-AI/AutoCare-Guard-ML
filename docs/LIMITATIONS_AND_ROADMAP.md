# 公开实现的限制与路线图

## 当前边界

- 仓库不包含真实售后服务事件数据、内部测试集、生产 checkpoint 或内部策略规则。
- `HeuristicJudge` 只用于验证 API、解析、路由、审计和监控链路，不代表模型效果。
- `sshleifer/tiny-gpt2` 只用于训练流程冒烟测试，不代表售后车辆风险研判质量。
- Qwen SFT/LoRA 配置需要使用者自行准备合规数据、模型权重和适配的 GPU 环境。
- Docker、Kubernetes 和 vLLM 文件是参考模板，未声明已在公开环境完成生产部署或容量验证。
- SQLite 审计与进程内限流适合单实例验证，多实例环境需替换为集中式组件。
- XGuard 等公开数据是安全识别底座，不等于真实售后车辆风险样本。

## 后续可验证工作

- 使用有明确许可证的公开数据建立固定 train/validation/test 划分。
- 为规则基线、小模型和 Qwen checkpoint 分别生成带数据版本的评测报告。
- 增加解析失败率、紧急动作误报率和人工复核改判率检查。
- 在实际目标硬件上记录吞吐、P95/P99 延迟和资源占用。
- 接入集中审计、网关限流和可回滚的模型注册平台。

公开仓库只报告可由对应数据、配置和命令支持的结果；内部项目结果不能由公开样例直接复现。
